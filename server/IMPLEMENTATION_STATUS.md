## 안전한 개발 절차
1. `develop`에 작은 기능 단위로 구현·검수한다. `main`은 사용자의 별도 검수/승인 전 변경하지 않는다.
2. Secret, 실제 사용자 비밀번호, 운영 세이브는 저장소에 기록하지 않는다.
3. 자동 E2E는 독립 `TEST` 사용자와 빈 슬롯에서만 수행한다.
4. 실서비스 Worker는 코드 커밋만으로 배포되지 않는다. 별도 배포 및 실 API 호출 테스트 결과를 명확히 구분한다.
5. 단계별 완료 보고에는 실제 확인한 테스트, 비용, UX, 회귀 영향 및 미검증 항목을 모두 기재한다.
