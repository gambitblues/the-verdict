# THE VERDICT — 개발 수용 기준 및 단계별 검수

개발 대상: `develop` (운영 `main` 불변). 실제 사용자 세이브와 Secret은 테스트 대상에서 제외.
이 문서는 구현 현황을 과장하지 않기 위한 작업·검수 체크리스트입니다. 기능 구현, UX/UI, 토큰 최적화, 사실 검증, 회귀 테스트를 모두 통과해야 '완료'로 표시합니다.

## AI 적용 원칙 — 몰입 우선 (2026-11-04 사용자 확정)
1. **AI는 게임의 몰입감이 실제로 높아지는 순간에만 사용한다.** 법정 발언, NPC 고유한 반응, 상황에 따라 달라지는 대화처럼 정적인 규칙·문구로 해결하기 어려운 지점이 우선이다.
2. **단순 나열·요약·재포장은 AI를 쓰지 않는다.** 이미 존재하는 증거·쟁점·통계·판결 데이터를 같은 내용으로 다시 보여주는 기능은 삭제하거나 기존 UI로 간결하게 처리한다.
3. **플레이어는 재판장이다.** AI가 판결 방향을 추천하거나 사건의 숨겨진 진실을 노출하거나 기존 엔진의 증거 채택·판정·형량을 바꾸지 않는다.
4. **플레이 화면에는 기술 검증 상태를 노출하지 않는다.** `AI 문장 검증 완료`, `사건 기록 원문` 같은 배지는 제거하고, 진단은 로그·테스트·운영자 도구로 확인한다.
5. **AI 사용에는 비용 대비 경험 가치가 있어야 한다.** 필요할 때만 호출하고 한 번에 묶어 생성·검증하며 캐시·재사용·실패 시 원문 복구·사실관계 검증을 적용한다.
6. **기능 완료 조건:** 몰입 개선 UX + 사실 일치 + 토큰 비용 + 회귀 테스트 + 실제 화면 완주를 함께 검증한다. 구현·테스트·실배포·실사용 검증 상태를 구분한다.

## 안전한 개발 절차
1. `develop`에 작은 기능 단위로 구현·검수한다. `main`은 사용자의 별도 검수/승인 전 변경하지 않는다.
2. Secret, 실제 사용자 비밀번호, 운영 세이브는 저장소에 기록하지 않는다.
3. 자동 E2E는 독립 `TEST` 사용자와 빈 슬롯에서만 수행한다.
4. 실서비스 Worker는 코드 커밋만으로 배포되지 않는다. 별도 배포 및 실 API 호출 테스트 결과를 명확히 구분한다.
5. 단계별 완료 보고에는 실제 확인한 테스트, 비용, UX, 회귀 영향 및 미검증 항목을 모두 기재한다.

- 2026-11-04 UX 간소화: 판결 탭의 재판연구원 장문 나열 패널과 수동 AI 문장 검토 버튼 제거. 기존 쟁점별 현황 유지, 브라우저 `bench` 요청 코드 제거. Worker `/ai/bench`는 하위 호환을 위해 남겼으며 호출하지 않음. 변경 후 로컬 회귀 테스트는 미실행.
