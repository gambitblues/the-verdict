# P3-13 — 사람 상시 검수 없는 자동 사건 품질관리 (초기 단계)

## 운영 철학
THE VERDICT의 목표는 '운영자가 매 건 승인'하는 공장이 아니다. 사건은 오프라인 AI가 사전 생성하고, 다층 검수에서 걸러진 것만 재고에 저장한 뒤 두 판사의 세계에서 중복 없이 사용할 수 있어야 한다. 사람은 정책 변경, 표본 감사, 검증 자체의 품질 평가 등 예외에만 개입한다.

## 이번 단계 구현
- `server/worker/src/terra_auto_triage.cjs`: 자동 판정기 `triage()`. 기존 초안·세계 시트 일치성, 18회 시뮬레이션의 사건 ID/해시, 실제 6개 탭 브라우저 QA의 동일 시트 해시, 미완성 법률 메모, 중복 ID/원형, 재고 한도를 전부 검증한다. **모두 통과한 일반 사건만** `decision=stock` 상태의 비공개 재고 후보로 분류한다.
- 의학·성범죄·살인 등 고위험 유형은 별도 검토 큐(`audit`)로 분류한다. 현재 두 번째 독립 AI 감정기는 없으므로 이 큐의 자동 통과를 주장하지 않는다.
- 실패한 사건은 `quarantine`으로 격리한다. **이 판정기는 `ready`로 변경하거나 운영 게임·공개 인덱스에 배포하는 권한이 없다.**
- `tests/terra-browser-qa.mjs --sheet pending/<id>/world-sheet.json`: 성공 시 `pending/<id>/browser-qa.json`을 생성하고 시트 SHA-256과 실제 재판 3회 결과를 기록한다. 실행에 실패하면 보고서를 만들지 않는다.
- `tests/terra-generate.cjs`: `qa-result.json`에 정확한 사건 ID를 포함한다.
- `tests/terra-stock.cjs --inspect <id>`: 두 가지 QA 보고서를 대조하여 `stock`, `audit`, `quarantine` 여부를 출력한다. **현재는 읽기 전용 판정 명령**으로 실제 재고 등록은 하지 않는다.

## 현재의 연결 한계
- 진짜 '무인 자동 보충'을 완성하려면 스케줄러, API 호출 비용 한도/중단 기준, 검증 결과가 보증되는 저장소, 안전한 원자적 재고 저장, 배당 잠금, 추가 독립 AI 심사, 운영 배포 전 품질 표본 감사가 더 필요하다.
- `browser-qa.json`은 로컬 결과물로 암호학적 인증서/신뢰된 서명이 아니다. 사용자가 임의로 파일을 조작할 수 있는 환경을 넘어서면 서버에서 재실행하거나 서명해야 한다.
- 세 번의 실제 브라우저 테스트는 세 가지 숨겨진 세계를 하나씩 강제로 검사하는 테스트가 아니다. 별도의 18회 엔진 시뮬레이션을 병행한다.
- `main`, 기존 100개 세계 시트, 사용자 세이브와 공개 재고를 변경하지 않는다.

## 향후 구현 순서
1. 스케줄 기반 비용 상한이 있는 사건 생산과 자동 QA 배치
2. 고위험 사건의 독립 검증 AI 및 감사 비율 정책
3. 비공개 재고 DB의 동시성 안전한 적재/원자적 배당
4. 조건을 충족한 사건만 게임에 등록하고 이력·환원 보장
