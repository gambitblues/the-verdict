# 인수인계 — 방향성 · 사건 쓰기 · 지금 어디까지

새 채팅을 시작하면 `CLAUDE.md` 다음으로 이 파일을 읽는다. 일하는 규칙·테스트·배포 절차는 `CLAUDE.md`에 있고,
여기에는 **왜 이렇게 만드는지, 사건(세계 시트)을 어떻게 쓰는지, 지금 어디까지 왔는지**를 둔다.
작업이 한 단계 끝나면 맨 아래 '지금 어디까지'를 고친다.

## 1. 게임의 방향

- **한 줄:** 풋볼매니저식 판사 시뮬레이션. 판사로 임관해 40년 동안 사건을 맡고, 판결로 경력·평판·인맥이 쌓인다.
- **최우선 가치는 몰입감.** 기능을 붙이기 전에 "판사로서의 체감이 늘어나는가"를 먼저 본다.
  게임 문구는 고등학생도 아는 쉬운 말로 쓰고, 게이지나 수치는 화면에 드러내지 않는다.
- **판사 실력은 '법정 기록으로 가려낼 수 있었는가'로 잰다.** 진실을 맞혔는지보다, 법정에 나온 자료와 증언으로
  그 결론을 낼 수 있었는지가 기준이다. 실력 점수는 판결 때 한꺼번에 보여 주고, 여론은 점수에 넣지 않는다.
- **재판 화면은 하나뿐이다 (v8.1, 사용자 확정).** 모든 사건은 `trial_play.js`의 6개 메뉴
  (사건·기일·증거·증인·주문·판결)로 진행한다. 새 사건 데이터가 다른 화면이나 엔진으로 넘기면 안 된다.
  "새 재판 시스템을 만드는 게 아니라 기존 재판 시스템에 새 사건을 연결하는 것."
- **'이거 해 본 건데' 느낌을 없앤다.** 40년 경력이면 약 370건을 맡으므로, 사건 수를 계속 늘린다.
  같은 사건이라도 실제로 일어난 일이 세 갈래(했다 / 안 했다 / 사정이 다르다) 중 하나로 정해져서 판마다 다르게 흐른다.
- **나중에는 서버와 AI가 인물·사건 생태계를 만든다.** 그래서 데이터는 직렬화할 수 있는 평범한 객체로 두고,
  `offerPair(slot)`처럼 서버로 옮기기 쉬운 모양을 유지한다. 지금은 서버 없이 로컬에 저장한다.
- **인물은 영속한다.** 법조인 약 210명과 전문가 명부가 있고, 과거 인물은 의미 있는 연결이 있을 때만 다시 등장한다.
  사건의 사실·진실은 생성 때 고정하고, 진술·전략·관계만 상황에 따라 바뀐다.

## 3. 사건 쓰기: 씨앗 → 세계 시트 → 게임

### 3-1. 좋은 씨앗의 기준
`seeds.md`의 **100~109번이 기준 견본**이다. 016~099번은 틀에서 찍어낸 초안이라, 기획자가 100번대 형식으로 고쳐 쓰고 있다.
좋은 씨앗에는 다음이 있다.
- 그 사건에만 있는 장면 (예: "수술실 감시장치의 8분 공백", "차량 뒤에 남은 옆집 주민의 운동화 자국")
- 갈리는 지점 한두 개
- 세 갈래를 한 줄씩. 서로 다른 사실로 갈려야 한다. "고의가 입증된다 / 하지 않았다"처럼 요약만 바꾼 문장은 쓰지 않는다
- 꼭 넣고 싶은 증거. 원본 기록, 기기, 시각이 다른 자료

씨앗에서 쓰는 칸은 판례/출처, 형사/민사, 죄명·청구, 무슨 일, 갈리는 지점, 세 갈래, 증거, 메모다.
모든 사건에 똑같이 들어간 문장(심리 전개, 판사가 피할 오판, 미래 변수 같은 틀 문장)은 무시한다.

### 3-2. 시트 만들기 (Claude)
1. **id:** 씨앗 제목에 `[adv-cr-016]` 같은 꼬리표가 있으면 그것을 쓰고, 없으면 종류별 다음 번호를 쓴다.
   `world-sheets/template.json`을 복사해 `world-sheets/cases/<id>.json`을 만든다. 견본은 `cases/clinic-001.json`이고,
   기존 집필 사건을 옮긴 시트는 `cases/v6-*.json`과 `world-sheets/hand/*.json`에 있다.
2. **출처:** 판례 번호는 출발점일 뿐이고 서사는 창작이다. 그래서 `source.type`은 `original`로 두고,
   note에 "판례 번호는 검색 출발점, 사실관계는 창작"이라고 적는다. `real_case`는 판결문에서 사실을 실제로 가져왔을 때만 쓴다.
   판례 번호는 게임 데이터(`world_sheets.js`)에 들어가지 않는다. 빌드할 때 `source`를 지운다.
3. **종류 맞추기:** 재판 틀은 형사·민사·결정형 세 가지다. 형사는 `charge`로 쓴다.
   민사는 `claim`(금액, 적정 범위 `fair`)으로 쓴다. 행정 사건(처분 취소)은 결정형 `decision`(yes 취소 / no 유지)으로 쓴다.
   가사 사건은 금액이 있으면 민사, 없으면 결정형이다. 결정형은 세 세계마다 `decide: "yes"|"no"`를 둔다.
4. **세 세계 설계:** `did`(했다) / `didnt`(안 했다) / `reason`(했지만 사정이 다르다). 세계마다 다음을 쓴다.
   - `legal`: 결론 한 줄. 무엇이 성립하고 왜 그런지
   - `act`: 판결문 '범죄사실' 수준으로, 누가 무엇을 어떻게 얼마나 했는지
   - `motive`, `cause`, 그 세계에만 있는 `timeline`
   - 형사는 `sentencing`(수단·정도·횟수·상황·피해·피해자·계획성·사후 태도)을 세 세계 모두에 채운다
   - `knows`: 피고인·피고가 아는 것. **`didnt`와 `reason`을 꼭 채운다.** 법정의 당사자 신문 답이 여기서 나온다
5. **자료(`records`):**
   - 처음 나오는 자료(`first: true`) 3개가 증거 카드가 되고, 나머지는 '주문'으로 받아 낸다. 주문 문구는 `unlock`에 쓴다.
   - 자료마다 세 세계의 내용을 모두 쓴다. **세계에 따라 같은 자료가 다르게 나오는 것이 판사가 추리하는 길이다.**
     세 세계에 똑같은 내용을 두면 한쪽 세계와 모순되기 쉽다. 기존 시트에서 공문·카메라·문자·실측 기록으로 여러 번 고쳤다.
   - 처음 자료 3개만으로 세 세계가 다 갈리면 안 된다. 주문해야 갈리게 만든다.
   - 자료에는 기록 그대로의 문장만 쓴다('18:42:13 두 손으로 밈'처럼). '뒷받침한다', '단정할 수 없다' 같은 평가는 쓰지 않는다.
   - 기기 시계가 틀리면 `devices.clockOffsetSec`에 적는다. 법정에서는 시각 다툼 자료로 쓰인다.
6. **증인(W1…):** 3~4명. 이해관계가 서로 달라야 한다. 직업·나이·`stake`·`leans`·성향(정직·압박·기억)을 정한다.
   - `saw`(세계마다 본 것)는 **두 문장 이상**으로 쓴다. 첫 문장이 증인의 첫마디가 된다.
     앞 절반은 "직접 본 것" 질문의 답이 되고, 뒤 절반은 "시각과 순서" 질문의 답이 된다.
   - 증인이 실제로 보지 못한 범위도 정해 둔다.
7. **문장 규칙:**
   - 이름은 `{A}` `{B}` `{W1}` 토큰으로 쓰고, 조사는 `{A|이}` `{B|을}`처럼 쓴다.
   - 성별은 무작위라 성별 단어를 쓰지 않는다. '아내'를 품은 '쫓아내' 같은 말도 걸린다.
   - 성범죄·스토킹·부부·연인·이혼·양육·불륜 사건은 두 당사자가 항상 이성이다. `OPPOSITE` 규칙이 자동으로 적용된다.
   - 문체는 판결문체로 쓰고, 감각적인 묘사는 하지 않는다. 미성년자 관련 성적 내용과, 따라 할 수 있는 범행 방법은 쓰지 않는다.
   - `common`(다툼 없는 사실)에는 세 세계 모두에서 참인 것만 쓴다. 이 칸은 게임의 '사건' 메뉴에 그대로 나온다.
8. **`status`는 `review`로 둔다.** `draft`는 게임에 들어가지 않는다.
9. **검사와 빌드:**
   ```
   node tests/world-sheets.test.cjs        # 구조·세 세계 구별 (review부터는 실패로 막음)
   node tests/match-engine.test.cjs        # 세계 불변·판마다 다른 재판·판결 평가
   node tests/build-sheets.cjs             # world_sheets.js 다시 만들기 (시트를 고치면 반드시)
   ln -sfn "$(npm root -g)" node_modules && node tests/match-play.mjs && node tests/browser-smoke.mjs; rm node_modules
   ```
10. **표시:** 끝낸 씨앗은 `seeds.md` 제목 줄 끝에 `→ <id> (v8.x)`를 붙인다. develop에 커밋하고, 배포는 요청이 오면 한다.

### 3-3. 시트가 게임에 들어가는 방식
- `tests/build-sheets.cjs`가 review·ready 시트를 `world_sheets.js`로 만든다.
  기존 60건에 없는 시트는 사건팩 `world-sheets-v1`로 배당 풀에 들어간다.
- `match_play.js`의 `toCurated(s)`는 시트를 집필 사건 모양으로 바꿔 법정에 넘긴다.
  처음 자료는 증거로, 나머지 자료는 주문으로, 시트 인물은 증인으로, 진실은 세 갈래 답으로 바뀐다.
- 기존 집필 60건은 원래 글 그대로 진행한다. 시트에서는 '다툼 없는 사실'(`common`)만 가져온다.
- 매치 엔진(`match_engine.js`)과 그 화면은 게임에 연결돼 있지 않다. 개발 화면 `dev/match-engine/`에서 시트를 시험할 때만 쓴다.
