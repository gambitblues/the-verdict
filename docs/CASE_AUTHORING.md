# 사건 시나리오 기획 양식

기획서를 `docs/case-template.json` 모양 그대로 써 주면, 개발에서 아래 파일들로 나눠 넣고 검사(`narrative-qa`)를 돌려 바로 출제 풀에 올린다. 칸 이름은 코드와 똑같으니 영어 그대로 둔다.

| 기획서 칸 | 들어가는 곳 | 게임에서 보이는 곳 |
|---|---|---|
| `meta` | `content-packs/*.json` | 사건 배당 카드(제목·꼬리표·아이콘), 유형별 출제 비율 |
| `story` | `curated/part*.js` | 사건 개요, 막 구성, 선고 뒤 결말, 몇 년 뒤 진실 |
| `profile` · `sex` | `curated/registry.js` | 인물카드 나이·직업·학력, 성별 규칙 |
| `court` · `evidence` · `late` · `witnesses` | `curated/detail*.js` | 쟁점, 증거 카드, 증인 신문, 새 증거, 구형·청구액·결정 |
| `followUps` | `curated/follow*.js` | 재판장 주문(기일 사이 자료 요구·재소환·설명 요구) |
| `party` | `curated/party*.js` | 피고인·당사자 신문 |

완성 예시: `docs/case-examples/criminal-murder-campus-conflict.json`(형사), `civil-shaded-roof.json`(민사), `decision-guardian-signature.json`(결정형). 실제 게임 데이터에서 뽑은 것이라 깊이를 그대로 따라 쓰면 된다.

## 1. 먼저 정할 것: 사건 모양과 진실 셋

- **kind**
  - `criminal`(형사): 유죄·무죄와 형량을 정한다.
  - `civil`(민사): 금액을 정한다.
  - `decision`(결정형): 인용·기각만 정한다. 심리 1회 뒤 바로 결정하고 금액은 없다.
- **진실 셋(`truth`)이 모든 것의 뼈대다.** 게임은 새 게임마다 셋 중 하나를 몰래 고정하고, 진실에 따라 달라지는 답과 자료가 그 진실을 따라간다.

  | 키 | 형사 | 민사·결정형 |
  |---|---|---|
  | `did` | 혐의가 맞다 | 청구(신청)한 쪽이 맞다 |
  | `didnt` | 혐의가 틀렸다 | 상대가 맞다 |
  | `reason` | 행동은 있었지만 사정이 있다(감경·정당방위 등) | 일부만 맞다 |

- **그래서 기획에서 가장 중요한 일:** 증인 답, 새 자료, 피고인 답을 진실 셋마다 따로 쓰는 것. 셋이 서로 **말이 맞아야** 한다. 같은 진실 안에서 증인 2와 피고인과 새 증거가 같은 그림을 그려야 판사가 추리할 수 있다.

## 2. 칸별 분량 (검사 기준 — 모자라면 배포 불가)

| 칸 | 필요한 양 |
|---|---|
| `story.claims` | 정확히 2문장 (양쪽 주장) |
| `story.acts` | 정확히 4개 (발단·전개·위기·절정) |
| `story.truth` | `did`·`didnt`·`reason` 셋 다 |
| `story.endings` | 형사 `convict`·`acquit`, 민사·결정형 `claimant`·`respondent` |
| `court.issues` | 2~3개 (`i1`~`i3`). 모든 증거·질문·주문은 이 중 하나에 묶인다 |
| 형사 `court.charge` · `demand` | 법정형 범위(년) 안의 구형. 벌금 구형이면 `charge.fine`에 상한이 있어야 함 |
| 민사 `court.claim` | `amount`(만 원) ≥ `fair` 범위의 최대값 |
| 결정형 `court.decision` | 7칸 모두 |
| `evidence` | 정확히 3개, 12칸 모두 |
| `late` | 1개 (공판 중 도착하는 증거) + `reason` + `rebut` |
| `witnesses` | 정확히 3명. 증인마다 질문 3~4개, 그중 처음부터 열린 질문 2개 이상 |
| 진실별 답 | 사건 전체에서 진실에 따라 달라지는 증인 답이 2개 이상 (실제로는 증인마다 1~2개 권장) |
| `followUps` (형사 살인·성범죄) | 6개 이상 |
| `followUps` (그 밖의 형사·민사) | 5개 이상 |
| `followUps` (결정형) | 2개 이상, 모두 `"now": true`(그 자리 질문) |
| `party` | 질문 3개, 각 질문에 진실 셋의 답 |
| `court.rebut` · `closing` | 각 1~2문장 |
| `profile` | A·B 직업과 나이 범위는 꼭. 학력·혼인·자녀는 이야기에 필요하면 |

## 3. 증거 한 장 (`evidence`, `late`, 주문으로 받는 자료)

| 칸 | 뜻 | 좋은 예 |
|---|---|---|
| `title` | 증거 이름 | 펜션 계단 조명 기록 |
| `kind` | 종류. 화면 그림(영상·메신저·감정서·통화기록 등 11가지)이 이 말로 정해진다 | 시설 관리 기록 |
| `by` | 낸 쪽 | 검찰 / 변호인 / 원고 / 피고 |
| `when` | 자료의 시점 | 사건 당일 23:40~00:30 |
| `excerpt` | 원문 발췌. 기록 그대로의 말투로, 숫자와 시각이 있으면 좋다 | 23:51 켜짐 / 23:54 꺼짐 … |
| `shows` | 이 증거가 말하는 것 | 추락 시각 전후로 조명이 꺼져 있었다 |
| `caveat` | 한계 | 꺼졌다는 사실은 사고와 범행 모두 설명할 수 있다 |
| `how` | 확보 경위. 판사가 믿을지 판단하는 재료 | 사흘 뒤 관리 PC에서 내려받음, 시계 미보정 |
| `check` | 판사에게 주는 힌트 | 부회장이 말한 10분과 맞춰 보세요 |
| `issue` | 묶이는 쟁점 | i2 |
| `side` | `p` 검찰·원고 쪽 / `d` 피고인·피고 쪽 / `n` 중립 | d |
| `flaw` | 약점 종류. 증거 반박 장면에 쓰인다 | `none` · `timing`(시각) · `source`(출처) · `illegal`(위법 수집 → 배제 가능) |

- 주문으로 받는 자료는 `excerpt`·`shows`·`side`를 진실별 `{did, didnt, reason}`로 써도 된다. 같은 자료를 요구해도 진실에 따라 내용이 다르게 나온다.

## 4. 증인 (`witnesses`)

- `role`: 관계와 직업이 드러나게 쓴다(예: 펜션 관리인). 이름은 쓰지 않는다. 나이와 경력은 역할에서 자동으로 맞춘다.
- `story`: 배경 2문장.
- `stake`: 이해관계. 증인의 태도(협조·회피·번복)를 계산할 때 쓰인다.
- `says`: 첫 진술. 1인칭이고, 끝에 마침표를 찍지 않는다.
- `lead`: 유도 질문. 상대가 이의를 거는 장면에 쓰인다.
- `q`: 판사가 고르는 질문.
  - 진실과 상관없이 답이 같으면 `a`에 문자열을 쓰고 `side`를 붙인다.
  - 진실에 따라 다르면 `a`에 `{did, didnt, reason}`을 쓴다.
  - 숨은 질문은 `"hidden": true`로 두고, 그 질문을 여는 질문에 `"next": ["q4"]`를 쓴다. 꼬리 질문은 이렇게 만든다.

## 5. 재판장 주문 (`followUps`) — 2회차 이후 재미를 만드는 곳

주문은 판사가 기일 사이에 "이 자료를 내라 / 이 사람을 다시 불러라 / 이걸 설명하라"고 하는 것이다. 노드 하나가 주문 하나다.

| `type` | 뜻 | 반드시 함께 쓸 칸 |
|---|---|---|
| `records` | 기록 제출 (통화·출입·결제 내역 등) | `evidence` |
| `original` | 원본 제출 (캡처 대신 원본, 원본 파일 정보 등) | `evidence` |
| `alibi` | 알리바이 자료 | `evidence` |
| `expert` | 감정 의뢰 | `evidence` |
| `compare` | 두 자료 대조 | `evidence` |
| `witness` | 새 증인 신청 | `witness` (`role`·`story`·`stake`·`lead`·질문 3개) |
| `recall` | 이미 나온 증인 재소환 | `recall: {"w": 증인번호(0~2), "q": [새 질문 2개 이상, 진실별 답 1개 이상]}` |
| `explain` | 양쪽에 설명 요구 | `answer: {"p": "...", "d": "..."}` |

- **`to`**: `p` 검찰·원고 / `d` 변호인·피고 / `both`.
- **`day`**: 이 기일부터 열린다(1~4). 5기일부터는 `recall`·`explain`만 나온다.
- **`after`**(열리는 조건, 선택):
  - `{"heard":"1:q2"}`: 증인 1의 q2를 들은 뒤 (증인 번호는 0부터)
  - `{"got":"n1"}`: n1 자료를 받은 뒤
  - `{"miss":"n1"}`: n1이 없거나 거절된 뒤
  - `{"done":"n1"}`: n1을 결과와 상관없이 처리한 뒤
  - `{"contra":"i1"}`: i1 쟁점에서 진술이 엇갈린 뒤
  - 여러 조건 묶기: `{"any":[…]}` 하나라도 / `{"all":[…]}` 모두
  - 조건에는 **앞에 쓴 노드만** 쓸 수 있다.
- **`have` / `none`**: 어떤 진실에서는 자료가 아예 없으면 `"have":{"didnt":false}`로 표시하고, `none`에 "그런 기록은 없습니다"류 답을 쓴다.
- **형사에서 변호인에게 증거를 요구하는 주문**은 거절할 수 있다(입증 책임이 없으므로). 그래서 `none` 답이 반드시 있어야 한다.
- **없음·거절 뒤 길:** 위 두 경우처럼 빈손으로 끝날 수 있는 노드에는 `{"miss":"그 노드"}`로 열리는 다른 길 노드가 꼭 하나 있어야 한다.
- **필수 구성:** `recall` 1개 이상, `explain` 1개 이상, 3기일 이후 노드(`day`≥3이거나 `got`·`miss`·`done` 조건) 1개 이상.
- **결정형:** 모든 노드에 `"now": true`를 붙이고 주로 `explain`으로 쓴다. 심리 자리에서 바로 묻는 질문이 된다.

## 6. 당사자 신문 (`party`)

- 형사는 피고인(`"who":"A","role":"피고인"`)에게, 민사·결정형은 한쪽 당사자에게 묻는다.
- 질문 3개, 각각 진실 셋의 답을 쓴다.
- `side`(선택): 그 답이 어느 쪽으로 기우는지. 당사자 말은 증거가 아니라서 기본은 중립이다.
  - `p` / `d`: 답에서 무언가 새어 나올 때만 쓴다.
  - `m`: 판단을 어렵게 하는 사정.
- 형사 피고인은 20% 확률로 진술을 거부하고, 거부는 불리하게 계산되지 않는다. 답을 쓸 때 이 점은 신경 쓰지 않아도 된다.

## 7. 인물 고증 (`profile`, `sex`)

- **`profile`:**
  - `job`: 직업
  - `age`: `[최소, 최대]` 나이 범위
  - `deg`: 학력
  - `mar`: 혼인
  - `kids`: 자녀 수
  - 두 사람 나이 관계가 중요하면 `"younger":"A"`(A보다 어림), `"same":"A"`(A와 동갑대)를 쓴다.
- **`sex`:** 이야기가 성별에 기댈 때만 쓴다. 쓰지 않으면 무작위다.
  - `"A":"여"`: A의 성별을 고정
  - `"AB":"diff"` / `"same"`: 두 당사자가 이성 / 동성
  - `"W":{"1":"diffB"}`: 증인 1이 B와 이성 (`sameA`·`sameB`·`diffA`·`diffB`)
- 성범죄·스토킹·부부·연인·이혼·양육·불륜 사건은 따로 쓰지 않아도 두 당사자가 자동으로 이성이 된다.

## 8. 문장 규칙 (검사에 걸리는 것)

- **인물 부르기:**
  - 당사자 `{A}` `{B}`, 증인 `{W1}` `{W2}` `{W3}`, 변호사 `{L}`. 이름은 게임이 넣는다.
  - 이름 뒤 조사는 항상 `{A|이}` `{A|은}` `{A|을}` `{A|과}` `{A|으로}` 꼴로 쓴다. `{A}가`처럼 쓰면 이름에 따라 틀린다.
  - 형·오빠·누나·언니 호칭은 `{A>B}`(B가 A를 부르는 말)로 쓴다.
- **성별을 단정하는 단어 금지:** 남자, 여자, 남성, 여성, 아빠, 엄마, 남편, 아내, 장남, 장녀, 누나, 오빠, 언니, 사위, 며느리.
  - 다른 낱말 속에 섞여도 걸린다. 쫓아**내** → 아내, 참**여자** → 여자, 심**사위**원 → 사위.
  - 증인 `role`에서는 허용한다.
- **쉬운 말:** 고등학생이 읽을 수 있게 쓴다. 게이지 수치는 쓰지 않는다. 법률 용어는 꼭 필요한 것만, 풀어서 쓴다.
- **사건 사이 반복 피하기:** 다른 사건과 같은 문장이 반복되면 검사 수치가 올라간다.

## 9. 넘겨줄 때

- 사건 하나에 JSON 파일 하나로 준다.
- 칸을 비워 두면 개발에서 채우지 않고 되묻는다. 단, 다음 칸은 비워도 개발에서 맞춰 넣는다.
  - `meta.icon`, `meta.tag`
  - `profile.deg`
  - 형사 `charge`의 법 조문
- 새 사건이 들어가면 출제 풀 건수와 유형 비율이 바뀐다. 몇 건을 어느 유형으로 추가하는지 함께 알려 주면 된다.

## 10. Case Factory v7: 실제 판례 기반 FM형 사건 설계 (필수 기획 기준)

### 10-1. 수집·각색 및 출처 검증

- 신규 원형 목표: **형사 50 / 민사 25 / 가사 20 / 행정 5 = 100건**. 이는 *판례 원형* 목표이지 고정 시나리오 100건 목표가 아니다.
- 법제처·대법원·법원 등에서 **공식적으로 공개된 판례·판결요지·법령만** 법률 근거로 쓴다. 뉴스는 사건 소재를 찾는 단서이지 판결 확정 사실이 아니다. 비공개 판결서, 실명·연락처·주소·피해자를 특정할 단서는 수집·재현하지 않는다.
- 사건별로 별도 **기획 검증표**에 판례 사건번호, 선고일, 법원, 원문 URL, 열람일, 관련 조문과 사건 당시 적용 법령, 사실관계가 확인된 문단, 법리의 적용 범위, 각색 사항을 기록한다. **기획 검증표는 게임 데이터 JSON에 넣지 않는다.** 출처를 검증할 수 없는 내용은 판례에서 확인된 사실이라고 소개하지 않는다.
- 원본 판례의 인명·지명·금액·직업·관계·시간은 충분히 각색한다. 제3자가 실제 당사자를 재식별할 수 있는 조합은 피한다. **범행 방법의 구체적 모방 지침이나 증거 인멸 회피 절차가 아닌**, 사건 전후의 관찰 가능한 행동·시간·장소·객관적 흔적·양측 주장을 구체적으로 쓴다.
- **법리와 절차는 각색하지 않는다.** 형사 구성요건·고의·인과관계·증거능력·무죄추정·검사의 증명책임, 민사의 청구원인과 당사자 주장·입증, 가사·행정의 절차적 특성을 구별한다. 대법원 법리판단을 1심의 사실인정 과정으로 바꿀 때는 공개된 사실관계만 근거로 쓰고, 새 증거는 반드시 가상 설정임을 내부적으로 구분한다.
- 현 게임의 `meta.kind`는 `criminal / civil / decision`뿐이다. **가사·행정은 게임상 가장 가까운 절차에 매핑하되**, 해당 분야의 실제 소송·심판·신청·처분 취소의 차이를 먼저 검증한다. 모두 무조건 `decision`으로 넣지 않는다.

### 10-2. FM식 '고정 법률 — 생성된 세계 — 관찰 가능한 기록' 3층

1. **고정 법률(원형)**: 사건에 필요한 법적 요소, 증명책임, 허용 가능한 절차, 판단 기준은 변하지 않는다.
2. **생성된 세계(숨은 진실)**: `story.truth.did / didnt / reason`은 세 가지 **서로 물리적·시간적으로 가능한 사건 실체**다. 각 실체에 누가, 언제, 어디서, 무엇을 했고, 왜 그 결과가 일어났는지 인과 흐름이 있어야 한다.
3. **기록된 세계(재판자료)**: `evidence`, `late`, `witnesses[].q[].a`, `followUps`, `party`는 위 실체에서 발생한다. 판사는 이 자료만으로 판단한다. **숨은 진실 = 자동 유죄·자동 인용**이 아니다.

현재 엔진은 원형당 **진실 셋 3개**를 선택한다. 별도의 무제한 시드 변수 엔진이 구현되어 있다고 가정하지 않는다. 기획자는 세 진실별로 사건 경위·증거·증언을 정합적으로 작성하며, 향후 확장할 인물·환경·물증 변수를 아래 점검표로 관리한다.

| 변수군 | 기획자가 정할 항목 | 게임에 나타나는 결과 | 제약 |
|---|---|---|---|
| 사건 경위 | 갈등, 사건 당일 순서, 의사결정, 결과 발생 시점 | `story.acts / truth` | 행동→결과의 인과관계 |
| 시간·공간 | 이동 경로, 시계 오차, 조도, 시야, 거리 | `evidence.when / how / caveat` | 같은 장소·시간이 모든 자료와 맞아야 함 |
| 물증 | 무엇이 남고 무엇이 남지 않았는가, 감정 한계 | `evidence / late / followUps.evidence` | 존재하지 않는 자료를 주문 결과로 창조 금지 |
| 증거능력 | 수집 주체·경위, 원본성, 위법 문제 | `flaw / how / caveat` | **위법수집=무조건 배제**처럼 단정하지 않음 |
| 증인 관찰 | 당시 위치, 지각 가능 범위, 들은 말의 출처 | `witnesses.story / says / q` | 보지 못한 순간을 직접 목격했다고 서술하지 않음 |
| 증인 성향 | 기억·정직·압박·이해관계·전문지식 | `stake / lead / a` | 성향은 진실을 아는 능력과 별개 |
| 당사자 전략 | 인정·부인·침묵, 자료 제출, 신청 시점 | `claims / party / followUps` | 형사 피고인 진술거부를 불리한 근거로 삼지 않음 |
| 후속 심리 | 원본 확인·재신문·감정·새 증인·누락 결과 | `followUps.after / have / none` | 이전 결과가 다음 결과를 여는 조건 지킴 |

**변수 사이의 종속성 예시:** 카메라가 사건 순간을 촬영하지 못했다면 CCTV의 다른 시간대는 기록될 수 있어도 그 순간을 직접 보여 주면 안 된다. 목격자가 현장 밖에 있었다면 사건 소리를 들을 수는 있지만 눈앞의 행동을 봤다고 답할 수 없다. 시계가 4분 늦었다면 해당 기기의 모든 시간 자료가 일관되게 어긋나야 한다.

### 10-3. 문장·현장 고증: 요약문이 아니라 사건기록처럼 작성

- `summary`: 당사자 관계 → 구체적 사건 경위 → 피해·분쟁 → 소송으로 이어진 이유를 쓰되, **판사에게 숨겨져야 할 사실을 확정적으로 말하지 않는다**.
- `acts` 네 장면: 각각 시간·장소·행동·발견 경위·법정에서 드러나는 정보 중 적어도 두 가지를 포함한다. 연극적 긴장감은 유지하되 판사가 보지 못한 숨은 진실을 전지적 시점으로 노출하지 않는다.
- `truth` 셋: '누가 했음/안 했음' 한 줄만 쓰지 말고 **사건 전 → 사건 순간 → 직후 → 객관적 흔적**을 이어지는 2~4문장으로 작성한다. 단, 기존 코드의 문자열 형식은 유지한다.
- `evidence.excerpt`: 문서·녹취·거래내역·진료기록·CCTV 확인서처럼 **자료 생산 주체의 문체**를 사용한다. 확인 가능한 시각·단위·인용 구간을 넣되 근거 없는 정밀 수치를 꾸며서 확정 사실처럼 쓰지 않는다.
- `shows`는 직접 확인된 내용, `caveat`는 다른 설명 가능성, `how`는 확보 경위, `check`는 다른 증거와 비교할 대상이다. 이 네 칸을 비슷한 문장으로 반복하지 않는다.
- `witnesses[].says / q[].a`는 직업·관찰 위치·시간 경과·기억의 한계에 맞는 **자연스러운 1인칭 구어체**로 작성한다. 모든 증인이 판례 요지 같은 전문용어를 읊지 않는다. 추측과 직접 본 사실, 전해 들은 말을 구별한다.
- 사건이 민감한 피해를 다루면 사실판단에 필요한 내용만 쓰고, 피해 장면을 불필요하게 자극적으로 묘사하거나 범행을 따라 할 수 있는 실행 절차를 제공하지 않는다.

### 10-4. 세 진실의 재판 플레이 품질검사

기획자는 JSON을 제출하기 전에 아래를 **did / didnt / reason 각각**에 대해 확인한다.

1. **타임라인**: 사건 전부터 신고·수사·제소까지 모든 등장인물과 자료의 시간표가 모순 없는가?
2. **인과관계**: 행위·피해·결과 사이에 가능한 설명이 있고, 경쟁하는 설명도 실제로 비교할 수 있는가?
3. **정보 접근**: 그 증인이 해당 장면을 실제로 보거나 들을 수 있었는가? 전문지식이 없는 사람이 감정 결론을 단정하지 않는가?
4. **증거 출처**: 촬영기기·문서 작성자·통신기록·물건의 원본/사본 및 확보 경로가 설정과 맞는가?
5. **진술 분기**: 3명 중 최소 2명의 실질 답변이 세 진실에서 갈라지고, 같은 진실 안에서는 증인과 새 증거가 서로 해명 가능한 관계인가?
6. **판결 차이**: 어떤 사실이 달라져야 유죄·무죄, 전부·일부·기각, 인용·기각이 달라지는가? 결말만 임의로 바꾸지 않았는가?
7. **절차·법리**: 증거능력과 증명력은 별개로 평가했는가? 입증 부족과 실제 결백을 혼동하지 않았는가? 판사가 요구할 수 없는 자료를 무조건 제출하도록 강요하지 않는가?
8. **후속 심리**: 두 번째 기일의 주문이 앞서 드러난 모순을 직접 겨냥하는가? 자료가 없거나 제출이 거부되면 합리적 대체 경로가 열리는가?
9. **게임성**: 적어도 두 증거의 대조, 하나의 증인 신빙성 판단, 하나의 의미 있는 후속 질문·주문, 서로 다른 합리적 판단 경로가 있는가?
10. **누설·반복**: `story.summary`와 `issues.open`에서 진실을 누설하지 않는가? 다른 사건과 문장·반전 구조를 그대로 복제하지 않았는가?

**제작 난이도는 자료를 무작위로 숨기는 방식이 아니라** 증거의 적법성·정확성, 서로 상충하는 정황, 쟁점 수, 보충 심리의 필요성으로 결정한다. 피고인 유죄 가능성 같은 숨은 점수를 UI에 노출하지 않는다.

### 10-5. 기획자료와 런타임 JSON의 경계

- `docs/case-template.json`의 **키 구조·자료형과 현행 게임의 고정 슬롯 수**를 유지한다. `truth`를 객체로 바꾸거나 `evidence` 개수를 늘리는 등 엔진 변경이 필요한 수정은 이 작업에 포함하지 않는다.
- 게임에 **실제 구현되지 않은** 잠재 능력치, 완전 동적 증거 생성, 판결 자동추론 기능을 이미 동작하는 것으로 설명하지 않는다. 현재는 진실 분기 텍스트·증언·증거·후속 주문의 정합성을 높여 FM식 변주를 구현한다.
- 기존 완성 예시 3건은 현행 게임에서 추출한 **호환성 기준 시료**다. 예시 자체를 임의로 재작성하거나 실제 판례에 근거한 사건이라고 표시하지 않는다.
- 제출 기준: JSON 파싱 가능, 모든 필수 슬롯 작성, 유형별 분량 충족, 문체/인물 토큰 검사, 세 진실별 사건 타임라인 수동 검수, 공개 출처와 각색 구분까지 완료.
