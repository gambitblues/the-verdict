# THE VERDICT v3.2 — 통합 개발 명세 (PDF 3종)
기준: `develop` v3.1 / 공개 `main` 변경 금지.
원본: (1) 재판 루프 설계안 6p, (2) 사건 다양성과 몰입 장치 2p, (3) 재판 엔진과 언론·여론 설계 8p.

## 반드시 보존
- 1심 확정, 항소/상급심 미지원, 판결 후 드라마는 뉴스·평석으로 처리.
- 현실 3시간 = 게임 하루, 10~22시 제안, 하루 최대 4건 수락, 두 세이브 슬롯 및 기존 NPC ID.
- 판결 실력은 증거·절차 판단으로만 산출. 언론·여론 및 비공개 진실은 판결 실력에 **직접 반영 금지**.
- 사건의 비공개 진실은 게임 화면에 공개하지 않는다. 사후 진실 공개도 해당 사건의 기존 판결을 소급 변경하지 않는다.
- 버튼은 고등학생에게 익숙한 쉬운 표현 사용: 재판일, 조사, 증거 쓸까/뺄까, 아직 남은 의문, 판결 리뷰.

## 개발 순서 (모두 필수 범위)
1. **1개 사건의 완성된 플레이 루프**: 3개 증거 판단, 2개 이의 카드, 1개 연기 결정, 조사 4, P/D/점수, 선고 이유 1~2개, 기사 2~3개, SNS, 사후 공개.
2. **엔진·UI 연결**: 현재 v3.1의 복수 runtime 스크립트 로딩/메모리 세이브와 충돌을 막아 통합. 한 번 누르면 즉시 진행되는 기존 단계를 선택형으로 교체하고 재판일 1/4 표시 및 선고 대기 사유 표시.
3. **언론·NPC 연결**: H/O/S와 판결 리뷰, 기자 5~6명, 변호사 스타일·지연/언론전, 대중에게 보이는 사실과 판사가 아는 사실 분리.
4. **콘텐츠 확장**: 사건 원형 30~40개를 개별적으로 검수하고 현재 100건 팩에 분기·반복 방지 적용. 100건을 곧 100개의 완성된 독립 드라마로 주장하지 않는다.
5. **장기 생애**: 관련 인물 재등장, 후일담, 연간 목표, 판사 경력·별명, 수년 뒤 사실 공개. 진실 적중률은 평가와 절연.
6. **QA**: 기존 세이브/로컬 오프라인/iPhone Safari/Chrome/자동 시뮬레이션/변수 분포/법조 점수 방화벽.

## 수치 불일치와 구현 해석
원문 3번 PDF 3p에 '기본 10%+중요도 1당 2%'라고 쓰면서 중요도 5가 14%라는 예시가 있음. 둘은 불일치한다. 임시 엔진 기본값은 중요도 1→11%, 5→15%(기획 2번의 10~15% 범위)로 설정; 게임에 연결할 때 밸런스 검수.
원문 확신 게이지의 흠 발견 정도는 0/0.5/1로 처리하며 P-D >= 30 조건은 유죄 점수에만 영향, 선고 버튼의 잠금 조건은 최소 재판일 횟수다.
대중에게는 표면 증거 강도만 노출한다. 불법 증거/진술 충돌은 공개 법정에서 직접 드러났을 때만 여론 변경에 반영.
사건 재등장 금지는 직전 20건을 검사한다. 동일 원형 재등장 시 진실 또는 핵심 증거 흠이 이전 배당과 달라야 한다.
