# THE VERDICT — 개발·검증·승인 배포 정책

## 브랜치
- `main`: 공개 베타, GitHub Pages에 배포되는 안정 버전. 사용자가 명시적으로 **"업데이트 배포해"**라고 승인하기 전에는 수정하지 않는다.
- `develop`: 기능 개발·버그 수정·데이터 확장 통합 브랜치. 모든 변경은 여기만 커밋한다.
- `feature/<name>`: 위험도가 큰 기능을 격리하는 선택형 작업 브랜치. 완료 후 develop에 통합한다.

## 개발 배포 게이트
1. 새 기능 요청 → develop에만 구현. 공개 URL은 바뀌지 않는다.
2. 코드 검토 및 테스트 → 문법·팩 스키마·게임 로딩·세이브 호환성·기존 NPC 데이터 무결성 확인.
3. 릴리스 준비 → 변경 내역, 테스트 범위, 알려진 문제, 롤백 방법을 기록한다.
4. 사용자가 명시적으로 배포 명령 → `develop`에서 `main`으로 PR 생성·검토 후 병합한다.
5. Pages 배포 완료 상태 확인. 실제 모바일 동작 검증은 별도 항목이며 GitHub Actions 성공과 동일하지 않다.
6. 문제가 있으면 이전 `main` 커밋으로 복구하되, 사용자 저장 데이터 형식과 마이그레이션을 먼저 검토한다.

## 검증 체크리스트
- 플레이어 1·2 로컬 저장 독립성, 새 게임/이어하기/저장복구 및 JSON 백업
- 진행 중인 재판·판결·NPC·가족·세계관 기록의 구버전 호환
- 현실시계와 배당(10~22시, 매시간 1건, 하루 최대 4건), 미수락 사건 이관
- 재판 연기·증인·반박·증거 제출·선고 조건 및 시간이 지난 뒤 재개
- 100개 사건팩의 구조 및 출처/증언/전개/결말 일관성
- iPhone Safari/Android Chrome, 노트북 화면과 로컬 오프라인 동작
- SW 캐시 갱신, 빠른 재접속, 이전 저장 복원
- 기기 간 클라우드 동기화는 미구현이며 별도 프로젝트 인프라 작업

## 주의
GitHub Pages는 main에서 배포되도록 확인/고정해야 한다. 공개 베타와 개발 베타의 URL은 혼동하지 않는다. 서비스워커 캐시나 계정 저장 데이터를 불필요하게 초기화하지 않는다. GitHub 커밋을 했다고 해서 QA를 통과했다고 표시하지 않는다.
