## 새 사건 자동 배당 파이프라인 — 코드 구현

- `terra-from-author.cjs generate`: Terra 후보 + 정식 월드시트 작성.
- `terra_auto_admission.cjs`: 집필자 고정 사실의 원문 보존, 확정 증거 출처, 월드시트·후속 주문, 18회 재판 시뮬레이션을 모두 통과한 경우에만 서명된 입고 파라미터 작성.
- `terra-from-author.cjs publish`: 독립 QA 프로젝트의 `shared_case_admit_sealed`을 호출하여 **재판 가능한 세계 시트와 단 하나의 봉인 진실을 사건 재고에 입고**. 재배당/진실 바꿔치기 금지.
- GitHub Actions `Author case intake QA`: `TERRA_AUTHOR_AUTO_ENABLED=1`이면 신규 입력 사건 제작, `TERRA_AUTHOR_AUTO_ADMIT_ENABLED=1`과 QA 전용 Supabase 키가 준비되어 있으면 통과 사건을 자동 입고. 추가 사람 승인은 필요하지 않음. `main` 또는 운영 DB 자동 변경은 없음.
- 운영 제약: 저장소의 QA 환경 변수와 Secrets가 준비되지 않은 상태에서 자동 배당이 실제 서비스에서 작동한다고 주장하지 않음. 신뢰성 검증은 코드 CI와 독립된 실계정 E2E로 수행해야 함.
- 검증 한계: 집필자 고정 사실을 **문자열로 보존**하는 것은 자동 검사할 수 있지만, AI가 만든 증언의 법률적·의미적 정합성이 보증되지는 않음. 의심스러운 사건은 배당 차단 및 추가 검토 대상으로 처리할 것.

## P4 자유 주문·AI 동적 조사 1단계 (2026-11-04)

사용자와 합의한 원칙: **실제 일어난 사건의 진실은 고정, 판사가 어떤 주문을 내렸는지에 따라 드러나는 법정기록은 변화**. 모델에 판결과 새로운 확정 사실을 위임하지 않는다.

- `server/worker/src/free_order_intent.js`: 판사의 자연어 주문을 **기존 월드시트의 미공개 `records` 중 하나로만** 해석하는 AI 분류기. 기존 사건의 진실 분기/증거 본문/미래 답변은 모델 프롬프트에 보내지 않는다.
- `POST /world/court/free-order`: 실제 로그인·초대·담당 판사·서버 기일·선고 전 상태를 모두 검증한 경우에만 호출. 기존 `ai_reserve/ai_finish` 비용·호출수 집계를 재사용. AI가 목록 외 자료나 질문의 답을 내보내도 서버가 거부한다.
- `shared_world.js` 주문 탭: 자연어 입력 → AI가 제안한 **기존 증거 대상**을 판사에게 확인 → 승인하면 기존 `/world/court/action`으로 제출 명령. 미확인 제안은 저장되지 않는다. 기존 선택식 주문은 유지한다.
- Worker `P4_FREE_ORDERS_ENABLED="0"`, 브라우저 `p4FreeOrders:false` **기본 비활성**. 독립 QA에서만 두 옵션을 명시적으로 켠다.
- `server/worker/test/free-order-intent.test.js`: 봉인 진실 누설 금지, 허위 기록 ID 거부, 사건에 존재하더라도 주문 불가능한 자료 거부, 불명확한 주문 반환 테스트.
- `server/worker/test/worker.test.js`: 서버 측 소유권/기일 확인, 실제 비용 예약과 모델 호출(mock), 법정 기록 자동 수정 금지 테스트.
- `tests/shared-world-ui.mjs`: 2인 모의 플레이에서 자연어 주문 입력 → 제안 승인 → 다음 기일 증거 제출 → 판결을 확인하는 브라우저 회귀.

**다음 2단계의 의도된 제한:** 이것만으로 AI가 새로운 CCTV·의료기록·추가 목격자를 생성하지 않는다. 새 증거를 허용하려면 사건별 **불변 사실 원장(fact ledger)**, 자료의 기원·관측 가능성·수집 가능성, 근거 사실 ID, 법정 제출·증거능력 검증, 불확실한 결론 거부가 먼저 필요하다. 실세계 데이터가 주어지지 않았는데 AI가 새로운 음주 사실을 확정하도록 허용하지 않는다.

**개발 방향 중요:** 원래 지시서의 최종 UI는 `trial_play.js` **하나의 6메뉴**다. 현 `shared_world.js` 6탭은 QA 단계의 별도 경로이며 원래 재판 엔진으로의 통합 미완료. P4 출시 판정은 계속 NO-GO.

## P4/P5 공유 법정 2인 직무·좌석 및 6메뉴 동기화 (2026-11-04)

**재판장은 사건을 개시/자동 배당받은 실제 플레이어**, **나머지 실제 플레이어는 배석판사**, **NPC는 반드시 배석판사**입니다. NPC가 재판장 좌석을 점유하거나 기일을 개정하거나 판결을 독자 선고할 수 없습니다.

- `028_joint_bench_roles.sql`: 사건별 고정된 인간 재판장 / 인간 배석 / NPC 배석을 `shared_joint_bench`로 판사 본인에게만 노출. 구성 이후 좌석 역할·인물 변경 금지. 서버에서 초대/사건 소유권/좌석 일치 검사.
- `GET /world/panel/bench`: 인증된 해당 재판부 구성원만 실제 좌석과 권한을 조회할 수 있음. 현재 등록된 사건을 개시한 실제 플레이어가 `chair`, 나머지 플레이어는 `associate`, NPC는 `associate`로 고정.
- `GET /world/panel/case`: 재판장뿐 아니라 배석 플레이어도 똑같은 공개 사건·초기 증거·이미 확정된 질문/주문/이월 자료·선고 기록을 읽음. **공판 개정과 선고는 재판장에게만 허용**하며, 인간 배석판사는 재판장이 연 기일에 증인신문·제출명령과 비공개 합의 투표에 참여한다. 봉인 분기, 추후 증언, 미확보 자료는 보내지 않음.
- `shared_world.js`: 기존 재판 메뉴 영역에 있는 공유 법정의 **사건 / 기일 / 증거 / 증인 / 주문 / 판결** 탭을 모든 재판관이 열람. 재판장/배석/NPC 명칭과 역할 표시. 인간 배석에게는 개정·선고 버튼이 없지만, 개정된 기일에서는 신문·주문 버튼이 보임. NPC는 합의 의견만 제공. 복귀/다른 판사 활동 뒤 공판·판결·공개 뉴스 갱신.
- 합의 선고는 **인간 2명 + NPC 배석 1명**의 의견을 집계하며 2:1 다수결만 확정 가능. 1:1:1이면 추가 심의 전에는 선고 차단. AI는 법정기록에 근거한 NPC 배석 의견만 작성하며, 법정의 사실이나 판결 주문을 만들어 덮어쓰지 않음.
- `017` 후속 기사와 `019` 공개 인물 연결 트리거는 기존처럼 서버 판결 원장에서 반영. 후속 기사의 게임 날짜가 도래하면 공개하고, 등록된 `publicNpcId`만 공통 NPC 객관적 이력에 연결. 개인 기억·관계도는 건드리지 않음.
- `world_feed.js` 기본 태블릿 **기사** 화면: 공개된 사건 배당·공판·판결·후일담·NPC 공통 변화만 별도 '공유 세계 공식 기록'으로 읽기 전용 표시하고 공통 NPC의 공개 상태를 접이식 목록으로 제공. 개인 기사·댓글·관계·세이브에 서버 사실을 섞어 쓰지 않음.
- 자동 브라우저 QA: `tests/p5-dual-judge-ui.mjs`로 서로 다른 두 판사 화면이 같은 공개 사건과 법정 원장을 표시하되 재판장만 개정/신문하고 배석은 의견 제출만 가능한지 검증. `tests/p5-panel-ui.mjs`로 독립된 여섯 번째 자동 배당 슬롯/합의 과정을 검증.
- 신규 SQL 및 API 코드는 **독립 QA 전용**이고 서비스 플래그는 기본 비활성. 운영 Supabase/Worker/세이브 미변경.

**출시 판정은 여전히 NO-GO**: 기존 `trial_play.js`의 개인 재판 데이터를 전역 서버의 `S.cases`로 섞지 않는다. 공유 사건은 현재 기존 재판 화면에 연결된 **별도 상태/서버 엔진**으로 동작하며, 개인 재판의 모든 연출·NPC 관계·상호작용과 완전히 동일한 컴포넌트를 재사용한 것은 아니다. 실제 QA 계정 두 개로 배당→공판→이월 증거→합의→선고→다음날 기사·NPC 변동까지 실서버 E2E가 통과해야 P4/P5 완료 판정이 가능하다.

## P4 비동기 게임시간 원칙 (2026-11-04 확정)

**실제 1일 미접속 ≠ 게임에서 1일 자동 결석**. 현실 시각은 사건 후보 오퍼 슬롯(10–22시)에만 사용한다. 게임 날짜는 서버의 `shared_world_clock.game_day` 단 하나만 존재한다.

- A 판사가 재판 **8건을 세계 10일의 동일 날짜**에 열면, `shared_hearing_open`은 세계 날짜를 한 번만 10일로 맞춘다. 사건 8건 때문에 8일을 덧붙이지 않는다.
- A가 미래 공판(예: 세계 12일)을 실제로 열면 공통 날짜가 12일로 전진하고 B도 공개 뉴스·NPC 이력에서 12일을 본다. 과거로 역행하지 않는다.
- B가 하루 접속하지 않았다면 진행 중이던 B 개인 사건의 기일을 자동으로 열거나 판결하지 않는다. B가 복귀할 때 `shared_judge_resume`이 과거로 밀린 개인 예약 기일만 **현재 공통 날짜 + 게임 2일** 이후로 보호 조정한다. A의 기일·판결·공통 뉴스는 수정하지 않는다.
- B의 복귀 보고에는 놓친 **공개 세계 사건의 변화**와 미처리 기일 수를 별도로 표시한다. 재접속 처리 재시도는 멱등적이어서 버튼을 연속 눌러 기일을 무한히 늘릴 수 없다.
- 주의: 아직 2인 실재판 엔진의 `VerdictCalendar.advanceTo`까지 대체하지 않았으므로 이 정책은 **서버 예약 기일·QA 세계 UI**에만 적용된다. 기존 싱글플레이 세이브의 시간은 그대로 둔다.

- `013_shared_hearing_progress.sql`: 실제 예정 기일을 열었을 때만 공통 세계 시계가 `max(현재 날짜, 열린 기일)`로 전진, 같은 날짜 여러 공판은 시간 중복 증가 없음
- `014_world_chronology_guards.sql`: 미래 날짜의 기사·NPC 생애 변화 공개 금지, 근거 없는 판결 기사·선고 후 공판 기록 생성 금지
- Worker `GET /world/catchup`: 서명된 판사 자신의 미처리 기일과 세계 날짜 차이 조회
- Worker `POST /world/resume`: 본인 판사 ID를 서버 JWT에서 결정하며 타 판사 기일을 건드리지 않는 복귀 RPC
- `shared_world.js`: 비동기 판사 복귀 상태 표시·복귀 버튼(독립 QA 옵션을 켠 경우만)

## P4 다음 단계: 봉인된 증인신문·증거 제출 명령 (개발 반영)

- `015_shared_court_actions.sql`: 법정 신문 및 증거 제출 명령을 **사건별·액션별 한 번만** 확정 저장하는 불변 법정 원장. 다른 판사는 접근할 수 없고, 실제 서버에서 열린 공판 기일에만 기록 가능하며 판결 후 추가 행위를 거부.
- `server/worker/src/shared_courtroom.js`: 사건 진실 `did/didnt/reason`을 서버에서만 읽고 해당 분기의 진술·주문 결과를 결정. 기일 전에는 봉인된 답이나 자료를 보내지 않음.
- Worker `GET /world/court/status`, `GET /world/court/history`, `POST /world/court/action`: 판사 본인 소유권 검증, 서버 공판 기일 확인, 신문·증거 명령 요청 기록 및 재조회. 브라우저가 제출한 `answer`, `branch` 등은 무시하고 서버에서 만든 결과만 사용.
- `shared_world.js`: 기존 게임 세이브와 독립된 공유 세계 미리보기 안에서 실제 서버가 승인한 공판인 경우에만 신문·주문 버튼을 표시. 본인 법정 기록만 표시.
- Worker `P4_COURT_ACTIONS_ENABLED="0"`, 클라이언트 `p4CourtActions:false`: 기본 비활성화. 독립 QA 환경에서만 명시적으로 두 설정을 모두 활성화.
- QA: `server/worker/test/shared-courtroom.test.js` 및 Worker/SQL 회귀 테스트로 분기별 답, 증거 선행조건, 접근 차단, 중복 액션, 기록 수정 금지 확인.

**남은 게임 연동:** 현재 `trial_play.js`의 기존 재판 절차와 공유 서버 액션을 연결하지 않았음. 서버가 승인하는 최초/추가 공판 일정, 후속 자료가 이월되었을 때의 단계별 공개, 판결문 검증 및 선고 확정, AI 답변 후 검증, 개인 NPC 기억 반영을 마쳐야 실제 2인 P4 재판이 완성됨.

## P4 공유 재판 실행 체인 — 이번 develop 추가 구현

- **공유 법정 진입**: `trial_play.js`의 기존 사건 목록에 공유 법정 진입을 연결하고, `shared_world.js` 화면을 기존 재판과 같은 **사건·기일·증거·증인·주문·판결 6개 탭**으로 정리했다. 원본 개인 재판 세이브와 사건 개체는 섞지 않는다.
- **016 `shared_court_begin`**: 서버가 판사 신원·사건 소유권·개정 기일·공통 세계 시계를 직접 확인한다. 최초 개정은 서버 현재 날짜, 추가 기일은 직전 완료 기일 다음 날 이후. 이전 기일에서 실제 법정 활동을 하지 않았다면 다음 기일로 넘어갈 수 없고 총 6기일 상한을 적용한다. 브라우저는 날짜·판사 ID를 선택할 수 없다.
- **018 이월 증거**: 증거 제출 명령 당일에는 `delayed`만 기록한다. 후속 기일을 열고 `shared_order_result_record`로 승인한 다음에야 봉인된 분기의 실제 자료·제출 거부·추가 지연 결과를 공개한다. 이전 기일에서 주문하지 않은 자료와 미선택 진실 분기는 공개되지 않는다.
- **증인신문·기록**: `shared_courtroom.js`가 공개 시점, 선행 질문, 개정 기일을 검증하고 봉인된 사건 원본에서만 답변을 결정한다. immutable `shared_court_actions`에 확정 기록을 저장한다. 클라이언트 임의 답변은 반영하지 않는다.
- **공유 선고**: `shared_judgment.js`와 Worker `POST /world/court/verdict`는 사건 분야에 허용된 판결 유형인지 확인하고, 최초 제출 또는 법정에서 실제 확인한 증거·증언만 판결 근거로 받는다. 판결 주문과 SHA-256 사건 기록 해시는 서버에서 만들고 `shared_judgment_publish`로 원자적 단일 판결을 확정한다. 판결 후 신문과 재선고는 차단된다. 다만 기존 `trial_play.js`의 상세 판결 점수·양형 산식과 동일한 계산이라는 주장은 할 수 없다.
- **017 후속 뉴스**: 선고 이후 사건의 공통 후속 소식은 서버 공통 날짜가 다음 게임 날짜에 도달했을 때만 한 번 발행된다. AI가 개별 관계자 인생을 임의 창작하지 않는다.
- **019 객관적 NPC 판결 연속성**: 서버가 미리 등록한 `publicNpcId`가 세계 시트의 인물에 정확히 연결된 경우에만 판결 사실을 공통 NPC 공개 이력과 뉴스에 추가한다. 개인별 관계·대화 기억 및 기존 사망·직업 상태는 그대로 보존한다. 안정된 NPC ID가 없는 구형 사건은 이름만으로 잘못 병합하지 않으며 자동 연결하지 않는다.
- **기본 안전장치**: Worker의 `P4_SHARED_DOCKET_ENABLED`, `P4_COURT_ACTIONS_ENABLED`, `P4_JUDGMENTS_ENABLED`는 모두 `"0"`. 게임의 `p4SharedWorld`, `p4SharedDocket`, `p4CourtActions`, `p4SharedVerdicts`는 모두 `false` 기본값. 독립 QA에서만 활성화한다.

**구현 경계:** 기존 `S.cases` 기반 개인 커리어 선고·NPC 감정·상세 점수와 공유 사건의 서버 선고가 자동 병합되는 것은 아니다. 공유 사건은 기존 사건 목록에서 진입하는 별도 서버 관리 재판이며, 개인 저장 체계와의 양방향 동기화, 개별 사건법·양형 엔진의 완전한 동일성, AI가 쓰는 실시간 후속 기사, 실제 2계정 E2E는 아직 검증 또는 구현이 필요하다.

**아래 기능은 아직 구현되지 않았으므로 P4 완료라고 주장하지 않습니다.**

2. **서버 봉인 진실·증거 단계별 제공:** 현행 세계 시트는 브라우저에 여러 진실 분기를 번들로 보유. P4 사건은 서버에서 진실을 봉인하고 담당 판사 전용 **공개 사건 카드/초기 제출 증거 API** 및 QA 전용 선택 미리보기까지 구현. 이후 기일별 **후속 증거 주문·증인신문·판결**의 허용 범위를 서버에서 판단해 내려주는 단계별 API와 기존 6메뉴 재판 엔진 적용이 필요. 기존 6메뉴를 그대로 유지해야 함.
3. **서버 판결의 실게임 확정:** `shared_judgment_publish`는 신뢰된 서버 판결 엔진에만 호출 가능하도록 남겨둠. 현재 `trial_play.finish`의 로컬 선고는 아직 서버 원장에 자동 확정되지 않음. 브라우저가 임의로 판결문을 올리는 경로는 도입하지 않음.
4. **동기화된 세계 시간:** 서버 예약 기일과 복귀 보호/동일 날짜 중복 진행 방지는 구현됐으나 `VerdictCalendar.advanceTo`가 이를 실제로 사용하지 않음. 두 판사의 동시 기일, 재시도, 오프라인 전환/충돌 처리 연결 필요.
5. **NPC 생애와 뉴스를 게임 데이터에 반영:** 공용 원장/API는 존재하지만, `S.npcDB`와 개인 `S.memories`의 객관적/주관적 분리·병합, `S.news`와 후속 사건 발생 적용이 미연결.
6. **2계정 게임 E2E:** 서버 데이터/화면 단위 테스트와 달리 실제 QA Supabase + Worker + 2개 테스트 세이브로 공통 사건 진행을 검증한 증빙은 없음.

## P4 판결·평점과 P5 합의부의 실제 서버 연결 (2026-11-04)

### P4: 판결 이후 상세 형량·배상액·평점

- `shared_sentence.js`: 형사 사건의 형법상 유기징역·벌금·무기·사형 허용 여부, 징역 6개월 단위, 집행유예 기간, 벌금 범위를 서버가 확인한다. 민사는 월드시트의 청구액 및 일부 인용 한도 안에서 배상액을 검증한다. 판사가 입력한 형량이 법정형을 벗어나면 선고되지 않는다.
- `shared_trial_grade.js`: 기존 `trial_core.js`의 **실제 `skill`과 `evaluate` 함수를 동일하게 호출**하여 공유 기록에서 확인된 채택 증거·증언·형량 결과를 평가한다. 증거의 하자·입증 방향 등의 `review` 메타데이터가 없는 구형 시트는 점수를 추정하지 않고 실패 처리한다.
- `023_scored_shared_judgments.sql`: 검증된 판결 원장 + 법정 판단 점수 + 종합 리뷰를 **단일 DB 트랜잭션**으로 생성한다. 이미 확정된 점수 변경도 허용하지 않는다.
- Worker에서 `P4_TRIAL_PARITY_ENABLED="1"`로 켠 경우에만 이 새 경로를 사용하며 기본은 비활성이다. 브라우저 `p4TrialParity:true`에서 형량·배상액 선택 UI가 나타난다.
- 간편 집필로 새로 생성하는 사건은 Terra가 증거별 `review`와 검증 가능한 법정형·청구액을 작성하도록 요청한다. 자동 입고 검사도 점수 계산에 필요한 메타데이터가 없으면 FAIL 처리한다. **기존 사건 파일은 변경하지 않는다.**

**정확한 일치 범위:** `VerdictTrialCore.skill/evaluate` 계산 함수 자체는 공유 서버가 재사용한다. 그러나 구형 `trial_play.js`의 모든 이의신청, 증거 부분채택, 양형 인자, 부수 명령, 여론 및 커리어 반영 데이터를 서버 기록으로 모두 이식한 것은 아니다. 공유 사건 평점은 `inputMode:server_disclosed_court_record`, `publicOpinion:neutral`로 명시한다. 그러므로 개인 재판 평가와 *수치가 무조건 동일하다*고 주장하면 안 된다. 실제 동등성 확보와 장기 커리어 동기화는 여전히 출시 차단 요인이다.

### P5: 기존 두 판사 + AI NPC 1명 공동 합의부

- `020`~`024` SQL: 두 기존 초대 사용자 UUID + 등록된 살아있는 공개 NPC ID로 합의부 생성. 인간의 의견은 다른 판사에게 제출 전 숨기고, 세 표의 **동일한 법정기록 SHA-256**을 요구한다. 투표는 수정·삭제할 수 없다.
- `p5_panel_routes.js`: 로그인한 판사가 기존 재판 계정과 공개 NPC 중 합의부를 구성, 각자 비공개 의견 투표, 현황 확인. 새 테스트 판사 계정은 생성하지 않는다.
- `p5_npc_deliberation.js`: **두 실제 인간 투표가 완료된 후** 모델이 공개된 증거·증언만으로 세 번째 의견을 생성한다. 봉인된 세계·인물의 개인 기억·두 판사의 표·비공개 심의 메모는 AI에 제공되지 않는다. 비용 제한/예약/사용 기록은 기존 `ai_reserve`/`ai_finish`을 따른다. 모델 실패 시 NPC가 의견을 낸 것처럼 처리하지 않는다.
- 다수결이 준비되면 주심 판사는 `/world/panel/finalize`에서 근거 증거와 법률상 형량·배상액을 제출한다. 결과 선택은 **서버의 다수 의견으로 강제**되고 법정 근거를 검증한 뒤 단 한 번 선고한다.

## 2026-11-04 — 공유 재판 엔진 통합 2차 (develop only)

이번 통합은 별도의 두 번째 법정 화면을 추가하지 않고, 개인 `trial_play.js`와 공유 `shared_world.js`가 동일한 `VerdictCourtSurface.frame/navigation`을 사용하도록 했다.

- **권한:** 실제 인간 재판장만 개정·증거 채택/배제·선고를 수행한다. 인간 배석판사는 개정 중 증인신문·주문 및 비공개 투표를 수행한다. NPC는 인간의 선고 권한을 갖지 않는다. 두 판사의 질문·주문은 공통 서버 원장에 즉시 기록된다.
- **서버 원장:** 030 migration의 `shared_evidence_decision_record`가 기일별 불변 증거 채택·조건부 채택·배제를 추가한다. 동일 기일 재전송은 멱등, 변경은 충돌, 다음 기일 재결정은 새 기록으로 남긴다.
- **판결 이유:** 기존 개인재판의 `VerdictTrialCore.REASONS` 항목을 공유 판결에서 선택할 수 있다. 서버는 근거로 든 증거/증언의 실제 공개 여부, 배제 여부, 미존재 이유를 검증한다. `shared_trial_grade.js`는 서버 증거 결정 및 근거를 개인 법정과 동일한 `VerdictTrialCore.skill/evaluate`에 넣는다. 기록이 없는 항목의 신빙성 지표는 추측하지 않고 오류로 종료한다.
- **NPC 합의:** NPC 배석판사에게도 **실제로 공개된 최초 증거 원문**과 신문 답변, 주문으로 넘어온 증거, 채택/배제 이력을 투입한다. 감춰진 진실·다른 두 판사의 투표·비공개 NPC 관계는 모델에 주지 않는다. 투표마다 서버 법정 기록의 해시를 검증한다.
- **최소 기일:** 신규 `verdict-world-sheet/v1` 사건은 개인재판과 동일한 `VerdictTrialCore.minDays(importance)`에 따라 최소 2~4번의 기일 및 모든 주문의 결과 확인 후 합의를 시작한다. 레거시 시트는 무단 변경하지 않는다.
- **비동기 접속:** 신문·주문·증거 결정을 실행할 때는 현재 열린 기일/세계 날짜와 권한이 필요하다. 다만 서로 다른 날 접속한 판사라도 **기록이 그대로이고 심리를 끝냈다면** 3인 합의 투표·선고할 수 있다. 다른 사건으로 세계 날짜가 바뀌어도 기결/미결의 판정은 서버가 정한다.
- **후속 세계:** 기존 `judgment_published` → NPC 공개 이력 → 다음 게임 날짜 기사 트리거 및 공동 경력 원장을 그대로 유지하며, 단 한 번의 선고만 확정한다.
- **회귀 테스트:** `server/worker/test/shared-courtroom.test.js`, `shared-trial-grade.test.js`, `p5_panel_routes.test.js`, `worker.test.js`, `server/supabase/test/shared-world.test.js`, `tests/p5-dual-judge-ui.mjs`.

**완료 범위:** 공유/개인 법정은 같은 6메뉴 외형, 핵심 증거·법률 판단 및 형량/배상액 평가 함수를 사용한다. 서버 비공개 사실은 법정 밖으로 내보내지 않는다.

**차이점 및 운영 차단:** 개인재판의 절차 밖 생활 연출과 상대측 NPC의 모든 임의 이의/연기 카드, 민간 여론 생성까지 공유 법정에서 1:1 복제한 것은 아니다. 본 커밋은 운영 SQL/DB/저장 데이터를 바꾸지 않는다. 출시 전에는 별도 QA Supabase·Worker와 2개의 실제 초대 계정으로 비동기 E2E(공판→주문→다음 기일→합의→선고→NPC/뉴스/경력)를 통과해야 한다.
